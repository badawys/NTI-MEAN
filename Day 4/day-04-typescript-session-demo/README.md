# Day 4 — Complete TypeScript Session Demo

This small project brings the Day 4 TypeScript topics together in one
course-enrollment workflow. It intentionally uses plain TypeScript so the
contracts are easy to inspect before they are used in Express, Angular, or
Mongoose code.

## Project structure

```text
day-04-typescript-session-demo/
├── src/
│   ├── models/
│   │   ├── course.types.ts
│   │   ├── user.types.ts
│   │   └── enrollment.types.ts
│   ├── services/
│   │   └── enrollment.service.ts
│   ├── utils/
│   │   └── api-result.types.ts
│   └── index.ts
├── dist/                 # Generated by npm run build; not committed
├── package.json
└── tsconfig.json
```

## Prepare and run

Use a current Node.js LTS release, then run these commands from this folder:

```bash
npm install
npm start
```

`npm start` first compiles the files into `dist/`, then runs the compiled
`dist/index.js` entry point.

## What the demo demonstrates

- Literal unions restrict course statuses, user roles, and enrollment states.
- Interfaces describe the shape of domain objects.
- `Omit`, `Partial`, and `Pick` derive safe DTOs from a source model.
- `ApiResult<T>` models success and failure without throwing for expected
  business-rule failures.
- The enrollment service narrows a union result with `result.success` before
  reading `data` or `error`.
- `readonly` protects identifiers from accidental reassignment.
- `Math.max` prevents a negative remaining-seat count when the approved count
  is greater than the configured capacity.

The demo is deliberately in memory. It does not connect to MongoDB or expose
an HTTP endpoint; those concerns are introduced after the TypeScript contracts
are understood.
